# Ataraxia 宣言的要求

この資料は、製品に求める成果と制約を記録するユーザー管理の正本である。ユーザーは資料を直接編集するか、エージェントに要求の追加・変更・削除を明示的に指示できる。エージェントは要求から開発計画を導いて実行できるが、ユーザーの指示なしに要求の意味や状態を変更してはならない。

以下の初期基準は、既存の[技術仕様書](SPECIFICATION.md)と[README](../README.md)から既存の製品上の約束を整理したものである。ユーザーは内容を直接修正できる。

## 要求の追加・変更

各要求は、利用者が観測できる成果または制約を一つ中心に記す。種別接頭辞付きの安定ID `REQ-NNN` を使い、要求する成果を宣言形で書き、観測可能な受け入れ条件、優先度、起源を記録する。`REQ` は製品要求、`NNN` は3桁の連番を表す。IDは変更・再利用せず、項目を廃止した場合も欠番のまま残す。実装上の構造や手順は、それ自体がユーザー要求でない限り指定しない。

旧参照 `ATX-REQ-NNN` は同じ番号の `REQ-NNN` を示す別名として有効である。新規参照では `REQ-NNN` を使い、旧別名を別項目に割り当てない。

優先度は「必須」「重要」「任意」、状態は「提案」「受け入れ済み」「基準」「充足」「延期」「廃止」を推奨する。提案の受け入れ、要求の延期・廃止、既存要求の変更を決定できるのはユーザーだけである。エージェントは実装と検証の後、受け入れ済みまたは基準の要求を「充足」にできるが、未達の受け入れ条件があれば報告する。

要求はこの資料への直接編集、または「……という要求を追加して」のような明示的な依頼で追加できる。要求の実装依頼だけでは、要求文、優先度、受け入れ条件を変更する許可にはならない。
