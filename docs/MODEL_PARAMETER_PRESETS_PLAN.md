# モデルパラメータプリセット移行計画

## 目的

モデルファイルと同じstemのJSONからモデル固有パラメータを読み込む動作を廃止し、プロジェクトやモデルファイルに依存しない、ユーザー共通の複数プリセットへ移行する。

## 設計

- 内蔵プリセットはGit管理する `configs/model-parameter-presets.json` に、個人プリセット・選択状態・内蔵値の上書きは `%LOCALAPPDATA%/Ataraxia/model-parameter-presets.json` に保存する。
- 初回移行時は既存の共有 `request_parameters` と旧形式プリセットを利用者領域へコピーする。元の共有値は有効設定として維持する。
- 各プリセットは安定ID、表示名、`request_parameters` を持つ。選択中IDとルートの有効 `request_parameters` を常に同期する。内蔵値の編集も個人ファイル上のoverrideとして保存し、内蔵カタログの変更や削除はしない。
- GUIで作成、値の保存、名前変更、削除、切替を提供する。最後の1件は削除できない。
- パラメータ欄の値は選択中プリセットを編集する。モデル選択は設定値を変更しない。
- 起動時・生成時にモデルstemのサイドカーを検索・読み込みしない。KoboldCppの共有 `startup_parameters` は既存どおり適用する。
- ID生成、値検証、選択状態遷移、ファイル保存を分離し、headlessテストでは一時データと偽ストアを使う。

## リスクと扱い

- 既存ユーザーの現在値を初回プリセットに複写し、初期化で元値を破棄しない。
- モデルstemサイドカーは読み込まなくなる。削除や書換えは行わず、ユーザーファイルとしてそのまま残す。
- 同一共有設定ファイルを使う全プロジェクトでプリセット一覧と選択状態を共有する。
- プリセット名の重複は大文字小文字を区別せず拒否し、空名・長すぎる名前・制御文字を拒否する。

## 追加変更の実行計画

ユーザー指示「主要なモデル系列の推奨パラメータを元に初期プリセット群を作成。それらはgit管理対象、それ以外にユーザーが追加したプリセットはgit管理対象外」に対応する。REQ-003のローカルKoboldCpp利用に関係し、現行仕様はプリセットを `koboldcpp-settings.json` に置くため、個人設定もGit差分になり得る不足がある。

| 順序 | 作業 | 受け入れ確認 |
|---|---|---|
| 1 | 公式のモデル系列推奨値を確認し、根拠URLと対象系列を含むGit管理カタログを作成 | Qwen、Llama、Gemma、Mistral、DeepSeekを含み、各値を根拠資料へ追跡できる |
| 2 | 内蔵プリセットとユーザープリセットの読み込み・保存境界を分離し、旧形式をユーザー領域へ移行 | 内蔵カタログはGit管理し、個人プリセットと内蔵overrideは `%LOCALAPPDATA%` のJSONだけへ永続化 |
| 3 | GUIで内蔵とユーザー作成を識別し、個人プリセットと内蔵値のユーザー上書きを個人ファイルへ保存 | 内蔵定義は変更されず、初期値への復元と個人項目のCRUDが動作 |
| 4 | 完全なJSON構造、移行・Git管理境界、推奨値と根拠をREADME・仕様へ反映 | ソース管理対象とユーザーデータの型・保存先・規則を仕様で照合できる |
| 5 | ヘッドレステストとWindows GUI統合テストを実行 | 通常・境界・旧設定移行と画面操作の回帰が成功 |

主なリスクは旧共有設定内のユーザープリセットの移行漏れ、初期値更新が個人設定を上書きすること、モデル系列を誤認すること。移行は元の設定を変更せず、ユーザー領域へ一度だけコピーする。系列は自動判定せずプリセット名と説明で選ばせる。
